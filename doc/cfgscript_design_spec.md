# cfgscript 设计说明书（Design Specification）

## 1. 引言

### 1.1 设计背景
在嵌入式系统、工具链、固件配置及复杂工程项目中，传统静态配置文件（如 ini / kv）在面对 **多环境差异、条件配置、批量生成** 等需求时显得力不从心。

`cfgscript` 的设计目标是：  
在 **保持配置文件“数据属性”** 的前提下，引入**受控的脚本能力**，通过“预处理 + 解析”的方式，实现灵活、可维护、可调试的配置系统。

### 1.2 设计目标
- 提供一种 **面向配置的领域专用语言（DSL）**
- 支持宏、条件、循环、表达式等能力
- 输出结果仍为**纯配置文本**
- 易于嵌入 C/C++ 工程（C99）
- 错误可精确定位到源文件与行号

---

## 2. 系统总体架构

### 2.1 两阶段处理模型

cfgscript 采用严格的两阶段模型：

1. **预处理阶段（脚本解释器）**
2. **配置解析阶段（KV Parser）**

```
原始配置文件
   ↓
[预处理解释器]
   ↓
展开后的纯配置文本
   ↓
[KV 解析器]
   ↓
cfg_t 运行期结构
```

---

## 3. 预处理解释器设计

### 3.1 功能范围
预处理阶段支持以下指令：

- `%define / %undef`：宏定义
- `%set`：表达式求值并存储
- `%if / %elif / %else / %endif`：条件控制
- `%for / %endfor`：循环展开
- `%include`：文件包含
- `${NAME}`：宏替换

### 3.2 符号表（Symbol Table）

所有宏、循环变量、set 变量统一存储在符号表中：

- Key：标识符名称
- Value：字符串（必要时转换为整数）

---

## 4. 表达式子系统设计

### 4.1 表达式语言定位
cfgscript 的表达式系统是一个**轻量级整数表达式解释器**。

### 4.2 编译原理基础
- 词法分析（Tokenizer）
- 递归下降语法分析（LL(1)）
- 语法制导解释执行

### 4.3 支持特性
- 算术：`+ - * / %`
- 比较：`== != < <= > >=`
- 逻辑：`! && ||`
- 括号
- 内建函数：`defined(NAME)`

---

## 5. 控制流结构设计

### 5.1 条件控制（if）
- 条件表达式求值
- active / inactive 控制
- 支持嵌套

### 5.2 循环控制（for）
- 块捕获
- 变量注入
- 块重放
- 符号表恢复

---

## 6. 预处理输出与调试支持

- 支持导出预处理展开文本
- 等价于 `cpp -E`
- 支持源文件行号注释

---

## 7. 配置解析器设计（KV Parser）

- 支持 `key=value` / `key:value`
- 自动忽略注释
- 类型推断：string / int / bool
- 运行期结构：`cfg_t`

---

## 8. API 设计原则

- 接口最小化
- 明确生命周期
- 错误可诊断

---

## 9. 总结

cfgscript 是一个基于编译原理思想实现的配置 DSL，其核心价值在于 **可维护性、可调试性与工程可控性**。
